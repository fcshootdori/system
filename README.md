# 슛도리 SHOOTDORI (Ver.0.1.14)

다음 카페 기반 슛도리 운영 앱 — **신청 → 주장 선정 → 드래프트 → 공지 이미지 → 경기 결과 → 기록 열람**을 한 곳에서.
WD_FUTSAL 운영 흐름과 경기기록시스템(승률계산기) 조회 기능을 합친 구조입니다.

- 정적 웹앱(빌드 없음) — GitHub Pages에 그대로 올리면 동작
- 데이터: Firebase Firestore (설정 전에는 **데모 모드**로 이 브라우저에만 저장)
- 회원은 **카페 닉네임 + 비밀번호(숫자 4자리)**로 접속 — 처음 접속 때 비밀번호를 정하고, 자동 로그인 지원. 운영진은 **운영모드**(운영진 비밀번호), 주장은 **주장 링크**로 드래프트 참여

## 메뉴 구성 (WD_FUTSAL과 같음)

- **일반 회원** — 링크를 열면 바로 회원 화면. 하단 메뉴(PC는 왼쪽 메뉴):
  - **홈**: MATCH REVIEW(지난 경기) + NEXT MATCH(다음 경기). 신청 기간에는 "참가 신청하기" 버튼이 하단 메뉴 위에 고정
  - **일정**: 달력(초록 신청 중 · 파랑 경기 예정 · 회색 종료), 날짜를 누르면 아래에 세부 일정
  - **⚽ 경기모드**: 회원 — 라운드별 포지션 · 실시간 스코어 · 득점자 · 라운드별 득점 / 운영진 — 라운드별 점수·득점자 기록(운영 › 경기 운영 › 경기 단계와 같은 화면), 두 팀 포지션 보기 / 주장 — 라운드별 우리 팀 포지션 지정(주장만 가능, 일반 회원·주장은 우리 팀 포지션만 보임)(골대 아래·하프라인 위 반쪽 경기장, 아래 명단의 유니폼을 끌어다 자리에 놓기, 누르고 자리 누르기도 가능, 포메이션 4-4-2·4-3-3·4-2-3-1·3-5-2·3-4-3)
  - **경기결과**: 경기기록시스템과 같은 구성 [경기 결과 | 전체 순위 | 개인 기록] — 핑크 vs 블루 시즌 전적·시즌 흐름·경기 카드 / 부문별 1위·기준별 순위(승률·득점·MOM은 15경기 이상) / 선수 카드·시즌 출전 칸·팀 평균 비교
  - **내 정보**: 내 이름(카페 닉네임) 선택, 내 기록 요약, 맨 아래 운영모드 입구
- **운영진** — 내 정보 맨 아래 "운영모드" → 비밀번호 (한 번 들어간 기기는 오른쪽 위에 운영모드 버튼이 생김). 메뉴:
  - **일정**: 달력(빈 날짜를 눌러 경기 추가, 경기 날짜를 눌러 수정·삭제·경기 메뉴로) / 목록
    - **회차**: 경기 추가·수정에서 한 경기에 회차를 넣으면 앞뒤 경기는 날짜 순서대로 자동으로 매겨져요. 취소된 경기는 회차를 쓰지 않고 다음 경기와 같은 회차로 표시되며(예: 750회 취소 → 다음 경기도 750회), "회차에서 제외"한 경기(설날 같은 이벤트)는 빠지고, 승률계산기에서 가져온 경기는 Game_id(718~)가 회차예요
    - **경기 취소**: 경기 날짜 → 경기 취소(사유 선택). 일정에는 남고 빨간색 "취소"로 표시, 회원 홈에 안내가 뜨고 신청은 막혀요. 취소 철회로 되돌릴 수 있어요
  - **경기**: 위쪽에 선택한 경기(이전/이후)와 단계 막대 고정 — 신청 → 주장 → 드래프트 → 팀 확정 → 경기 → 결과. 단계를 누르면 그 화면으로 이동
  - **공지**: 신청 명단 · 팀 구성 · 경기 결과 이미지와 카페용 텍스트
  - **회원**: [회원 관리 | 출석 관리] — 닉네임·이름(실명)·유형·별칭, 검색·유형 필터(운영진/정회원/휴면), 표에서 닉네임·유형·별칭 바로 고치기, 출석·출석률·최근 출석, 명단 붙여넣기, CSV 저장, 여러 명 선택해 유형 변경·삭제 / 기간별(전체·올해·최근 3개월) 출석 순위·연속 출석
  - **설정**: 팀 정보, 기본 경기 방식, 통합 시트(경기 기록·회원 명부), 데이터
- **주장** — 카페 닉네임으로 로그인하면(또는 운영진이 보낸 **주장 링크**로 들어오면) 오른쪽 위 👑 드래프트 버튼이 생기고, 그 팀 주장으로 드래프트에 참여
- **드래프트** (WD_FUTSAL 드래프트 방과 같은 흐름, 2팀은 축구장 왼쪽·오른쪽): ① 팀 색 선택(핑크·블루, 드래프트 시작 때 주장이 고름 — 먼저 고른 팀이 가져감) → ② 우선순위 추첨(카드 두 장, 숫자 작은 팀이 1순위 · 운영진 대신 뽑기/바로 추첨) → ③ 선수 선택 1-2-2-1-1-2-2-1 … (선수를 고르고 '선택 완료') → ④ 운영진 팀 확정. 확정 뒤에도 같은 축구장 화면에서 화살표로 선수를 옮겨 밸런스 조정

## 경기 시간에는 첫 화면이 '경기'
- 오늘 경기의 **시작 1시간 전 ~ 경기 종료 시간**에 앱을 열면 홈 대신 **경기** 화면으로 열려요 (운영모드는 **경기 운영**). 끝 시간이 없으면 시작 + 2시간까지.
- 앱을 열 때와 5분 넘게 다른 앱에 있다가 돌아왔을 때마다 — 그 사이 홈을 누르면 홈 그대로예요. 공유 링크(기록·신청 등)로 열면 그 화면 그대로.

## 포지션 (주장)
- 그 팀 **주장**(공동 주장 포함)이 경기 화면에서 라운드별 포지션을 정해요. 경기 종료 전까지 언제든 고칠 수 있어요.
- 주장을 알아보는 방법: 팀 명단에 들어 있는 주장(주장 목록 순서와 상관없음) → 이벤트 경기에 미리 정한 주장 → 주장이 따로 없으면(카페 구역대로 만든 팀) 팀 이름 "○○팀"의 ○○ 회원. 주장 링크로 들어온 기기도 주장.
- **[포지션 확정 · 팀원에게 공개]** 를 누르기 전에는 주장만 보고, 팀원·운영진에게는 빈 축구장 + "주장이 포지션 지정 중입니다". 확정 뒤에는 주장이 고치는 내용이 바로 보여요.

## MOM 선정 (주장)
- 운영진이 **경기 종료**를 누르면, **승리 팀 주장**(공동 주장 포함)이 자기 팀에서 MOM 1명을 뽑아요. **무승부**면 두 팀 주장이 각자 자기 팀에서 1명씩.
- 뽑을 차례인 주장의 홈 화면에 'MOM을 뽑아 주세요' 띠가 나오고, 경기 결과 화면에서 고르면 돼요(다시 누르면 바꾸기·취소). 득점 많은 선수부터 보여요.
- 운영진은 모든 팀 MOM을 대신 고를 수 있어요. MOM을 안 뽑은 경기는 최대 7일 동안 Firebase 정리를 미뤄요.

## 경기 종류

- **일반 경기**: 신청(참석 · 불참 · 운영진 협의) → 신청 마감 → 주장 선정 → 운영진이 팀 이름 입력(기본 "주장 닉네임+팀", 예: 준찬팀) → 드래프트에서 팀 색 결정 → 팀 확정. 팀이 정해지면 신청 화면이 **팀별 좌우 칸**으로 바뀌어요
- **이벤트 경기**: 경기 등록 때 두 팀 이름·색(·주장)을 미리 입력. 방식은 두 가지 — **주장만 미리 정함**(신청은 일반 경기처럼, 마감 뒤 주장 단계 없이 드래프트) / **팀원까지 미리 정함**(경기를 만들 때 두 팀 명단을 모두 넣음 — 회원 목록에서 고르거나 카페 닉네임 붙여넣기, 주장·드래프트 단계 생략). 회원은 홈 다음 경기 칸에서 [참석하기][불참하기]만 누르고, 처음부터 팀별 좌우 칸으로 보여요. 주장·드래프트 없이 "참석자로 팀 확정"
  - 748회(10/10)·749회(10/17)는 이벤트 경기(지진희팀=핑크, 준찬팀=블루) — `js/config.js`의 `EVENT_SEEDS` (회차+날짜가 맞을 때만 적용, 경기 수정에서 바꾸면 그 값이 우선)
  - 카페 댓글 구역([지진희팀]·[준찬팀])은 이벤트 팀으로 자동 연결
- 팀별 칸에서 운영진은 ＋추가(참석·불참·협의·팀만 지정), ✕빼기, ⇄다른 팀으로 옮기기
- 경기 결과에서 MOM과 지각은 따로 나눠 보여요

## 카페 댓글로 참석자 가져오기 (임시 기능)

정식 서비스 전까지 카페 댓글로 받은 참석자를 앱에 옮기는 옵션이에요. **설정 → 카페 댓글로 참석 받기**를 끄면 버튼이 사라지고 앱 신청만 써요.

1. 운영모드 → 경기 → 신청 단계 → **카페 댓글로 명단 가져오기**
2. 카페 신청 글의 댓글 전체를 복사해 붙여넣기 → 분석하기 (여러 페이지면 이어 붙이기)
3. 머리 댓글 구역별로 회원 일치 여부 확인 → **참석자 확정** → 확인창에서 한 번 더 확인

> ⚠️ **가져오면 기존 명단(참석·협의·불참)을 모두 지우고 붙여넣은 댓글로 새로 만들어요.** 앱에서 직접 신청한 사람·운영진이 추가한 사람도 지워져요 (이미 정해진 팀 구성은 그대로).

- 세 가지 복사 형식을 모두 읽어요: 모바일 앱(`진이` ↵ `작성자 26.10.04 12:17`), 모바일 웹(`* 진이` ↵ 시간), PC(`진이작성자 26.10.04 12:17`). "작성자"는 카페 글쓴이 아이콘 글씨라 닉네임에서 빼요
- 운영진의 `————마감————` 같은 공지 댓글은 참석으로 세지 않고, 마감 표시로만 써요
- **댓글 구역 = 팀** (748회 댓글과 승률계산기 명단 비교로 확인: [지진희팀] 14명 = 핑크, [준찬팀] 15명 = 블루, 협의 토토로 → 인원 적은 핑크 = 15:15). 확인 화면에서 "댓글 구역대로 팀까지 확정"을 켜면 바로 팀 확정 단계로 가요(마감 댓글이 있으면 기본으로 켜짐). 구역 이름별로 정한 팀 색은 기억해 둬요
- 운영진(작성자)의 머리 댓글로 구역을 나눠요: `[팀 이름]` → 참석, `[불참]` → 불참, `외 참석자(운영진 협의)` → 협의 대기(운영진 승인 후 참가)
- 대댓글 내용(참, 참석, 참스억, 촘속 …)은 자유롭게 써도 구역으로 판단하고, `불…`로 시작하면 불참, `(미정)`이 붙으면 미정 표시
- 회원 목록(이름·별칭)과 일치하면 회원, 일치하지 않으면 **게스트로 참석** (개인 기록 제외). 회원을 직접 고르면 그 닉네임이 별칭으로 저장돼 다음부터 자동 일치
- 다시 가져오면 명단을 새로 만들지만, 승인해 둔 협의 인원은 승인 상태 그대로
- **참석 ↔ 불참 바꾸기**: 신청 명단에서 [불참으로]·[참석으로], 팀별 칸은 이름 옆 ⋯ 메뉴(다른 팀으로 · 불참으로 · 빼기). [＋ 불참 추가]·[＋ 인원 추가]에서 이미 명단에 있는 사람을 골라도 고른 상태로 바뀌어요
- 주장 단계에서 **구역대로 팀 만들기**를 누르면 드래프트 없이 댓글 구역 그대로 팀을 나눌 수 있어요 (첫 번째 구역 = 1번 팀 색)

## 앱 설치 안내 (install.html)
- `install.html` — "슛도리 앱 설치 방법". 먼저 쓰는 브라우저(아이폰 사파리 · 갤럭시 삼성인터넷 · 안드로이드 크롬)를 고르면 그 브라우저 단계만 한 화면씩(위아래 스크롤 없이) 넘겨 보고, 마지막에 [앱 설치하러 가기]로 앱 주소를 열어요. 주소: https://fcshootdori.github.io/system/install.html
- 내 폰으로 보이는 브라우저에 "이 폰" 표시. 주소 끝에 #ios · #sam · #chr를 붙이면 그 브라우저 단계로 바로 열려요. 앱의 **내 정보 › 📲 앱 설치 방법 보기**, 로그인 화면 아래 링크에서 들어가요.
- 단계 그림은 `assets/install/*.webp` (실제 슛도리 홈 화면 + 브라우저 화면을 본뜬 그림).

## 로그인

- 처음 접속: 카페 닉네임(별칭도 인식) 입력 → 비밀번호 숫자 4자리를 두 번 입력해 정하기
- 다음부터: 닉네임 → 비밀번호 4자리(다 넣으면 바로 로그인)
- 자동 로그인을 켜면 이 기기에서 계속 로그인 유지, 끄면 이번 접속에만
- 내 정보: 비밀번호 변경 · 로그아웃 / 운영 > 회원: 로그인 등록 여부, 비밀번호 초기화
- 비밀번호는 저장하지 않고, 닉네임·비밀번호로 만든 열쇠(SHA-256)를 문서 이름으로 써서 목록 조회가 막힌 컬렉션에 둬요
- **Firestore 규칙 업데이트 필요**: `firestore.rules` 내용을 Firebase 콘솔 → Firestore → 규칙에 붙여넣고 게시 (auth·authset 컬렉션 추가). 업데이트 전에는 로그인 화면에 "비밀번호 없이 닉네임으로만 들어가기(임시)"가 떠요

## 신청 마감
- 최소 인원을 채워도 신청은 계속 받고, **경기일 전 목요일 0시(한국 시간)에 자동 마감**돼요. (토요일 경기 → 그 주 목요일 0시 = 수요일 밤 12시)
- 홈·일정·신청 화면에 "⏰ 신청 ○월 ○일 (목) 0시 마감"으로 표시돼요.
- 운영진은 그 전에 [신청 마감]으로 먼저 닫을 수 있고, 마감 뒤 [신청 다시 열기]를 누르면 그 경기는 다시 자동 마감하지 않아요.
- 설정 → 기본 경기 방식(또는 경기일 수정)의 '신청 마감'에서 '운영진이 직접 마감'으로 바꿀 수 있어요.
- 최대 정원을 넣으면 넘는 인원은 대기로 받아요(0 = 제한 없음).

## 📗 통합 시트 (Firebase + 구글 시트 함께 쓰기)
예전에 쓰던 **승률계산기 시트**와 **회원현황 시트**를 새 **통합 시트** 하나로 합쳤어요. 예전 두 시트는 앱에서 더 이상 쓰지 않아요.

| 무엇 | 어디서 | 이유 |
|---|---|---|
| 신청 · 주장 · 드래프트 · 포지션 · 경기 진행(라운드 점수·득점) | **Firebase** | 여러 사람이 동시에 보고 바로 바뀌어야 함 |
| 끝난 경기 기록 · 개인 기록 | **통합 시트** (경기 · 라운드 · 출전기록 · 개인기록 탭) | 쌓이는 기록은 시트에서 보고 고치기 쉬움 |
| 회원 명부 (연락처 · 회비 포함) | **통합 시트** (회원 탭) | 명부의 기준. 공개해도 되는 항목만 앱 서버에 반영 |

**흐름**
- 운영진이 경기모드에서 **경기 끝내기**를 누르면, 연결 키가 있는 운영진 기기가 잠시 뒤 그 경기를 통합 시트로 보내요 (MOM·지각을 나중에 고쳐도 다시 보냄).
- 경기결과 · 개인기록 화면은 **시트 기록**을 읽어요. 아직 시트에 없는 경기(진행 중·방금 끝남)만 앱 기록으로 채워요.
- 시트에서 점수·득점자·MOM 등을 고치면 앱 기록 화면에도 반영돼요. 다만 앱에서 같은 경기를 다시 고치면 그 경기는 앱 기록으로 다시 바뀌어요.
- 시트의 회색 칸(점수 합계·결과·MOM·득점 요약 · 출전 결과·득점)과 개인기록 탭은 자동 계산이에요 (시트 메뉴 **슛도리 › 기록 다시 계산**, 매시간 자동).
- 회원 탭 → 앱 회원 정보: 연결 키가 있는 운영진 기기에서 열 때 + 30분마다, 서버(GitHub Actions) 3시간마다.

**Firebase 가볍게 쓰기** (설정 › 통합 시트, 기본 켜짐)
- Firebase에는 **다가올 경기와 최근 경기만** 남겨요. 끝난 지 3일 지난 경기는 운영진 기기(연결 키 있음)가 시트에 옮겨진 걸 확인한 뒤(기록 지문 일치 + 원본 보관) Firebase에서 지워요.
- 지운 경기는 앱이 시트에서 받아 **읽기 전용**으로 끼워 넣어서 일정 · 홈 '지난 경기' · 경기 결과 화면 · 출석 · 회차가 예전과 똑같이 보여요. 고칠 내용은 시트에서 고쳐요.
- 지우기 전 경기일 문서와 라운드 문서 원본(신청자 · 주장 · 드래프트 · 포지션 포함)은 시트 숨김 탭 `앱원본`에 남아요.
- 속도: 시트 기록은 기기에 저장해 두고 바로 보여 준 뒤 뒤에서 새 기록만 확인해요(바뀐 게 없으면 내려받지 않음). Firebase는 기기 캐시(오프라인 저장)를 써요.
- Firebase에 계속 두는 것: 팀 설정 · 회원(공개 항목) · 로그인 · 진행 중/다가올 경기.

**통합 시트 탭**
- `회원`: 예전 회원현황 탭 그대로 (연번 · 가입일자 · 등급 · 닉네임 · 이름 · 생년월일 · 연락처 · 운영진 이력 · 장불 · 생일 · 1~12월 회비)
- `경기`: 경기ID · 날짜 · 회차 · 구분 · 핑크팀/블루팀 이름 · 방식(합산/라운드별) · (자동) 점수 · 결과 · 라운드 수 · MOM · 득점 · 출처 · 앱 기록 지문 · 받은 시각
- `라운드`: 경기ID · 라운드 · 핑크(A) · 블루(B) · 핑크 득점 · 블루 득점 — 득점 칸: `홍길동×2, 김철수, 이영희(자책)` (자책골은 상대 선수 이름 뒤에)
- `출전기록`: 경기ID · 이름 · 팀 · MOM · 지각(O) · (자동) 결과 · 득점 · 자책골 · 회원ID (`g_`로 시작하면 용병 — 개인기록에서 빠짐)
- `개인기록`: 시즌별 · 통산 순위 (승점 = 승×3 + 무, 승률 = 승 ÷ (승+패), 순위 대상 = 15경기 이상)
- `명부·…` / `보관·…`: 예전 시트에서 그대로 복사해 둔 참고용 탭 (앱이 읽지 않음)

**처음 설정 (한 번만)** — 앱 운영모드 › 설정 › 통합 시트 › [설정 방법]에도 같은 안내와 [코드 복사]가 있어요.
1. 운영진 계정으로 **새 구글 시트**를 만들어요. **공유하지 않아요** (회원 연락처가 들어감).
2. 시트 메뉴 **확장 프로그램 › Apps Script** → 기본 코드를 지우고 [`apps-script/Code.gs`](apps-script/Code.gs) 내용을 붙여 넣고 저장.
3. 함수 목록에서 **setup** 선택 → ▶ 실행 → 권한 허용. 탭이 만들어져요.
4. **배포 › 새 배포** → 유형 **웹 앱** · 실행 **나** · 액세스 **모든 사용자** → 배포 → 웹 앱 주소 복사.
5. 시트 새로고침 → 메뉴 **슛도리 › 앱 연결 정보** → 연결 키 확인.
6. 앱 운영모드 › 설정 › **통합 시트**에 웹 앱 주소 · 연결 키 → [연결 확인하고 저장] → **[경기 기록 보내기]** (지금까지의 기록 — 예전에 승률계산기에서 가져온 경기 포함 — 이 모두 시트로 들어가요).
7. 시트 메뉴 **슛도리 › 예전 회원 명부 가져오기** → 예전 회원현황 시트 주소 → 회원 탭으로 그대로 복사 (다른 탭은 `명부·탭이름`으로). 원하면 **예전 승률계산기 보관하기**로 원본도 참고용 보관.
8. GitHub 저장소 → Settings → Secrets and variables → Actions → New repository secret → 이름 `SHEET_API_KEY`, 값 = 연결 키 (서버 회원 자동 반영). 예전 `MEMBER_SHEET_ID` Secret은 지워도 돼요.
9. 다른 운영진 기기는 연결 키만 넣으면 돼요 (운영 › 회원 또는 설정 › 통합 시트).

- Apps Script 코드를 고친 뒤에는 **배포 › 배포 관리 › 수정 › 버전: 새 버전 → 배포** (웹 앱 주소는 그대로).
- 연결 키는 회원 명부를 읽고 기록을 쓰는 열쇠예요. 새어 나갔다면 시트 메뉴 **슛도리 › 연결 키 새로 만들기** 후 운영진 기기·Secret을 바꿔 넣어요.

## 회원 정보 (통합 시트 회원 탭 → 앱)
- **새로 불러오기**: 운영 › 회원의 [↻ 새로 불러오기]. 처음에는 새 회원·이름이 다른 짝을 확인하고 반영해요.
- **회원 맞추기**: 닉네임·별칭 → 시트 연번(닉네임이 바뀐 경우) → 한쪽 이름이 다른 쪽에 포함되는 유일한 짝(예: 우영 ↔ 우영우영우). 닉네임이 바뀌면 예전 닉네임은 별칭으로 남겨요. 시트 닉네임의 괄호 표기는 별칭으로 넣어요(스테이(stay) → 스테이, stay).
- **회원 구분 = 시트 등급** (VIP · 우수회원 · 슛도리 · 정회원 · 탈퇴회원). **운영진은 회원 명단의 체크박스로 따로 지정**해요.
- 탈퇴회원은 신청·이름 선택에서 빠지고(기록은 남음) 회원 명단 아래쪽 '탈퇴 회원'에 따로 모아 보여요. 시트에서 빠진 회원은 삭제하지 않고 '시트에 없음'으로 표시해요.
- **회원 정보 고치기**: 운영 › 회원 명단에서 닉네임이나 [수정]을 누르면 창이 열려요. 시트에 있는 회원은 닉네임·등급·가입일자·이름·생년월일·연락처·운영진 이력·장불(여부·사유·시작/해제일자)을 고치면 **통합 시트 회원 탭 그 줄이 바로 바뀌고**(생일 월·일, 맨 위 최종업데이트도 같이) 앱에 다시 반영돼요. 별칭·운영진 표시는 앱에 저장해요. 시트 칸을 고치려면 그 기기에 연결 키가 있어야 하고, Code.gs가 0.1.54 이후 코드여야 해요(설정 › 통합 시트 › 설정 방법에서 새 코드 붙여 넣고 새 버전 배포).
- **🔒 개인정보**: 앱 서버(Firestore)는 누구나 읽을 수 있어서 **이름·생년월일·연락처·장불 사유·생일·회비는 서버에 저장하지 않아요.** 연결 키를 넣은 운영진 기기에서만 시트에서 바로 읽어 보여 줘요. 연결 키는 기기(와 GitHub Secret)에만 둬요.

운영 > 설정 맨 위 **🧪 베타 테스트**에서 원하는 단계까지 진행된 샘플 경기를 만들어 기능을 시험해요.
- 시작 단계: 신청 중 · 신청 마감 · 드래프트 중 · 팀 확정 · 경기 결과까지 / 경기 종류: 일반 · 이벤트(주장만) · 이벤트(팀원까지)

- 샘플 경기(`sample: true`)는 운영모드에서만 보이고, 회원 화면은 '이 기기에서 샘플 보기'를 켠 기기만(내 정보) — **개인 기록·출석·회차에는 들어가지 않음**
- [샘플 모두 지우기]로 샘플 경기와 그 경기 기록만 삭제

## 1. 새 계정에 올리기 (GitHub Pages)

1. 새 GitHub 계정(또는 조직)에서 저장소 생성 (예: `system`, Public)
2. 이 폴더의 파일 전체를 저장소 루트에 업로드
3. 저장소 **Settings → Pages → Branch: main / (root)** 저장
4. 1~2분 뒤 `https://<계정>.github.io/<저장소>/` 접속 → 데모 모드로 바로 체험 가능
   (설정 → 데이터 → **체험용 샘플 데이터**로 회원 18명·경기일을 만들어 볼 수 있음)

## 2. Firebase 연결 (모든 회원이 같은 데이터 공유)

1. 새 계정으로 [Firebase 콘솔](https://console.firebase.google.com) → 프로젝트 만들기
2. **Build → Firestore Database** 만들기 (위치: `asia-northeast3` 서울 권장)
3. **Build → Authentication → 시작하기 → 로그인 방법 → 익명** 사용 설정
4. **Authentication → 설정 → 승인된 도메인**에 `<계정>.github.io` 추가
5. **프로젝트 설정 → 내 앱 → 웹 앱 추가** → 나오는 `firebaseConfig` 값을 `js/config.js`의 `FIREBASE`에 붙여넣기
6. **Firestore → 규칙** 탭에 `firestore.rules` 내용을 붙여넣고 게시
7. 접속 → 상단의 데모 모드 안내가 사라지면 연결 완료

> 데모 모드에서 쓰던 데이터를 옮기려면: 데모에서 **설정 → 백업 파일 받기** → (Firebase 연결 후 복원 기능은 다음 버전에서 추가)

## 3. 처음 설정 (운영모드 기본 PIN: `0000`)

1. **설정**: 엠블럼·대표 색·카페 주소·**운영 PIN 변경**
2. **설정 → 통합 시트**: 위 '📗 통합 시트 › 처음 설정' 순서대로 연결 (예전 승률계산기 기록은 이미 앱에 옮겨져 있어 [경기 기록 보내기]로 시트에 들어가요)
3. **설정 → 기본 경기 방식** (기본값: 핑크 vs 블루, 5라운드 합산, 최소 26명)
   - 팀 수 2~4, 라운드 수, 결과 계산(라운드 합산 / 라운드별 따로), 팀 색(고정 / 주장 선택), 최소 인원, 최대 정원, 드래프트 순서
   - 특정 날만 바꾸려면 **홈 → 경기일·경기 방식 수정**에서 그날만 변경
4. **회원**: 이름은 카페 닉네임 그대로. 오타·다른 표기는 별칭으로 등록

### 기록 계산 (승률계산기와 동일)
- 경기 = 참석한 경기일 수 (합산 방식: 5라운드 합계 스코어로 그날 승/무/패 1번)
- 승률 = 승 ÷ (승+패), 무승부 제외 · 승점 = 승×3 + 무
- 게스트(회원 명단에 없는 이름)는 개인 기록에서 제외

## 4. 경기일 운영 흐름

| 단계 | 누가 | 화면 |
|---|---|---|
| 1. 경기일 만들기 | 운영진 | 홈 → 새 경기일 |
| 2. 신청 | 회원(앱) / 운영진(카페 댓글 붙여넣기·직접 추가·게스트) | 신청 |

| 6. 팀 색 선택 → 팀 확정 → 밸런스 이동 | 주장 / 운영진 | 팀 |
| 7. 팀 공지 | 운영진 | 공지 → 팀 구성 |
| 8. 결과 입력 | 운영진 | 경기 → 5라운드 만들기 → 라운드별 점수·득점·자책골 → MOM·지각 |

## 버전

- 0.x는 정식 출시 전 버전, 수정마다 끝자리(0.1.1, 0.1.2…)를 올리고 "버전업" 때 0.2로 올림
- 버전 표기: `js/config.js`의 `APP_VERSION`
- 버전을 올린 뒤 `node scripts/stamp.mjs` 실행 → 모든 파일 주소에 `?v=버전` 꼬리표 (업데이트 직후 새 파일·예전 파일이 섞여 버튼이 안 먹는 캐시 꼬임 방지)
